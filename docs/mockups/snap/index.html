Snap, the morning index

Eleven comparison videos, six new widgets, four versions of each show and one mock-up. Your keep / reject marks and notes are kept in this browser only.

How to read the videos. Each is left | right, with the recording's sound and a brightness trace under each half.
  • A spike that stands on each note, with a trough between notes, is snap.
  • Rounded hills that drift on after the notes are mush.
  • A second brightening after a peak is a fake attack, and a reason to reject.
Judge on these 60 Hz videos, never in the live lab (the lab fades per screen refresh, so on a fast monitor trails are half as long). The order below is the judging order: V1, V2a, V2b, V6, V9, V4, V7, then the rest.

3. The show copies

Each show exists in four forms in shows/: the original (your edits, untouched), -knobs (the same widgets with only knobs turned: does code beat a knob?), -snap (the snap versions of the widgets you already use) and -new (the new widgets: hammer, handover and blade). The studio opens a show only by its song, so to play a copy: back up shows/<song>.json; copy shows/<song>-snap.json (or -knobs / -new) over it; set the copy's "id" back to the song id (the copies carry "id": "<song>-snap" and so on, while "song" is already the song id); open /?song=<song> (liebesleid or rach-concerto-2); and restore your backup afterwards. Or step it frame by frame at render.html?show=<id>&hz=60&scale=1 (the page the videos were made from). The scene check (scripts/checks/snap-scenes-check.mjs) runs Chrome with the software 2D canvas and software WebGL (SwiftShader), because the GPU canvas is not bit-stable on blurred fills and GPU WebGL (the gliss fluid) is not bit-stable at all, a flake that predates tonight; its baseline was taken from the commit before tonight's work.
